## 4. Formal Responses to Review Questions Q1–Q10

### Q1: Handoff task prompt 是否确认非空？
> **YES**。100% 确认非空。在 Handoff V3 中消除了 `spec.get("task_instruction", "")` 回退缺陷，统一从 `spec["current_task"]` 读取，并在 `validate_spec_task` 中增加了硬失败断言（若为空或缺失直接触发 `TASK_SCHEMA_ERROR` 终止）。经 48 次真实运行检查，所有 run 的 `task_prompt` 均非空并完整记录于 `runs/full-agent-handoff-v3/handoff_summary.json`。

### Q2: H2/H3 historical memory 是否真实由 Agent A 生成？
> **YES**。H2 和 H3 的 historical memory 均由真实 Agent A (`HistoricalMemoryWriter`) 在仅可见 base commit 源码与 commit 历史（$\le \\text{base\\_commit}$）的条件下由 Qwen2.5-Coder-7B 真实生成并记录于 `runs/historical-memory-writer/<task>/<seed>.json`，消除了任何人工硬编码 `base_stmt_map`。H2 与 H3 严格共享完全相同的 Agent A historical memory 记录。

### Q3: 修复后 H0/H1/H2/H3 TSR 分别多少？
> 修复后 48 次真实 Bubblewrap 沙箱运行的 TSR 结果为：
> - **H0 (No Memory)**: **0.2500** (3/12)
> - **H1 (Oracle Valid Memory)**: **0.2500** (3/12)
> - **H2 (Agent A Historical Memory, No Invalidation)**: **0.5000** (6/12)
> - **H3 (RoleMem Invalidation + Target Update Memory)**: **0.5000** (6/12)

### Q5: Track B 0/5 的真实失败原因是什么？
> 真实失败原因为 **`ENVIRONMENT_FAILURE`**：当 pytest 在 Bubblewrap 沙箱执行时，沙箱未将待测库源码目录正确挂载到 `PYTHONPATH`，导致在 collection 阶段直接抛出 `ModuleNotFoundError: No module named 'requests'` / `'werkzeug'`，测试根本未能执行到 assertion。同时，两个候选样本本身存在真实证据缺陷（Requests PR #2497 仅为安全通告政策文档，而非 Retry 常量；Werkzeug PR #1913 仅引入了 `samesite="None"`，并未包含 `secure=True`）。因此先前评测应标记为 `candidate evaluation = INVALID`。
